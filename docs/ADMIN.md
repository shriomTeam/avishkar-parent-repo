# Admin console

An operator console for the platform team. It is its own Cloud Run service (`prod-avishkar-admin`, code in
`apps/admin`, package `clinic_admin`). It is not part of the clinic web app, and clinic staff cannot reach it.

## What it does today

- **Clinics**: list and search every clinic, filter by status, see counts of clinics by status and of clinics with each
  feature on.
- **One clinic**: details, patients/leads/voice-call counts, staff list, features, and its admin log.
- **Features**: turn any installed feature on or off for a clinic, with an optional end date (a trial). A change keeps
  the clinic's own feature settings (`config`). A feature key that is not installed is refused.
- **Clinic status**: `trial`, `active`, `suspended`. A suspended clinic cannot sign in or accept invitations; its data
  stays. The form needs a confirmation tick.
- **Admin log**: every change is written to that clinic's `ops.audit_log` with `actor_type = admin`.

## How it is protected

- One operator account. The user name, password and cookie signing key are generated by Terraform (`admin.tf`) and kept
  in Secret Manager. They are never in a tfvars file, in GitHub, or in the repo. There is no default password: the
  service does not start without them, and production needs a password of 20 or more characters and Secure cookies.
- Session cookie: signed, `HttpOnly`, `SameSite=Strict`, `__Host-` prefix in production, 8 hours. Every form carries a
  token tied to the session. Pages send a strict Content-Security-Policy and `no-store`, and use no JavaScript.
- Login is throttled (5 failures in 15 minutes per address). The counter is in memory, so the service is capped at one
  instance.

## Database access

It connects as `clinic_system` (`DATABASE_SYSTEM_URL`), the role that bypasses row-level security. No new role exists.
Because RLS does not protect it, every query in `service.py` names the clinic it means. The console cannot change
tables or run SQL typed by a person.

## Run it locally

```bash
ADMIN_USERNAME=operator ADMIN_PASSWORD=choose-a-local-password ADMIN_SESSION_KEY=any-random-text-of-32-or-more-characters pnpm --filter @clinic/admin dev
```

Then open http://localhost:8003. Tests: `pnpm --filter @clinic/admin test` (needs the local database, migrated).

## Deploy

Set `admin_enabled = true` in `infra/terraform/envs/prod.tfvars`. A merge runs Terraform (creates the service, the
secrets and the service account), then `deploy.yml` deploys the image. To read the sign-in details, see the comment at
the top of `infra/terraform/admin.tf`. The password is in the Terraform state, like the other generated secrets.
